# Survey on Large Language Model Agents and Tool Use

## TL;DR
- Large Language Model (LLM) agents combine task-oriented reasoning ("Thought" traces) and external action execution (API calls and tool invocation) to dynamically retrieve information, execute code, and solve complex multi-step workflows [1][2].
- Transitioning from incremental local loops (such as ReAct) to global orchestration paradigms—including Directed Acyclic Graph (DAG) planners, multi-agent conversation frameworks (AutoGen), and stateful runtimes (LangGraph)—significantly improves multi-tool composition and execution reliability [3][4][5].
- Massive API catalogs and realistic environments (ToolBench, WebArena, Gorilla, API-Bank, and SWE-bench) demonstrate that while agents can master large-scale tool retrieval and repository-scale editing, they remain vulnerable to local optimization traps and multi-turn execution failures [6][7][8][9][10].
- Autonomous agent security is severely threatened by indirect prompt injections (IPI) and tool poisoning that exploit the "lethal trifecta" of privileged tool access, untrusted input processing, and external communication [11][12][13][14].
- Robust mitigation frameworks—such as step-level guardrails (TS-Guard), internal-state hallucination detectors, and error-recovery reinforcement learning algorithms (Fission-GRPO)—successfully enhance agent safety and multi-turn reliability [15][16][17][18].

## Background
Large Language Models (LLMs) have evolved from static text-completion engines into autonomous agents capable of interacting with external environments through specialized tools and APIs. Historically, early text generation models were limited to parametric knowledge, prone to factual hallucinations and incapable of performing real-time computations or external data retrieval. The introduction of the ReAct (Reasoning and Acting) framework bridged this gap by interleaving reasoning traces ("Thought") with action execution ("Action" and "Observation"), enabling models to dynamically adjust plans based on intermediate feedback [1]. Concurrently, self-supervised tool augmentation paradigms like Toolformer demonstrated that language models could be trained to autonomously decide when and how to invoke external APIs—such as calculators, calendars, and web search engines—without degrading their core linguistic capabilities [2].

As agent applications expanded beyond single-turn API queries, architectural frameworks evolved to support multi-agent collaboration and stateful workflows. Frameworks such as AutoGen established conversational multi-agent abstractions where specialized agents (e.g., AssistantAgent and UserProxyAgent) collaborate via dialogue and automated code execution [3]. Similarly, stateful graph runtimes like LangGraph introduced fine-grained primitives (`State`, `Nodes`, and `Conditional Edges`) supporting durable execution, persistence, and human-in-the-loop oversight [5]. These architectural advancements transformed LLM agents from isolated prompting experiments into robust, long-running systems capable of handling complex software engineering, enterprise web navigation, and automated data processing tasks.

## Architectural Frameworks and Planning Paradigms
The foundational architecture for tool-augmented agents relies on the synergy between reasoning and acting. The ReAct paradigm demonstrated that allowing models to generate intermediate reasoning thoughts before executing tool actions drastically reduces error propagation and hallucination on question-answering and decision-making benchmarks (such as HotpotQA and ALFWorld) [1]. However, incremental step-by-step frameworks often suffer from local optimization traps and myopia during long-horizon tasks. To overcome these limitations, planner-centric architectures have emerged, employing global Directed Acyclic Graph (DAG) planning combined with Supervised Fine-Tuning (SFT) and Group Relative Policy Optimization (GRPO) to optimize multi-tool composition and execution paths on benchmarks like StableToolBench [4].

In parallel, multi-agent orchestration frameworks have gained prominence. AutoGen provides an open-source framework where conversable agents communicate through customizable message exchanges, enabling decentralized multi-agent problem solving across coding and mathematics [3]. For complex, production-grade workflows requiring strict state management, low-level orchestration runtimes like LangGraph provide graph-based execution engines inspired by Pregel and Apache Beam [5]. LangGraph supports durable persistence via checkpointers, event streaming, and precise human-in-the-loop interventions (`interrupt()` and `Command`), allowing developers to seamlessly blend deterministic workflow control with flexible LLM-driven agent loops [5].

## Tool Augmentation, API Learning, and Code Execution
Equipping LLMs with massive toolsets requires specialized fine-tuning and retrieval mechanisms to manage thousands of APIs. ToolLLM addresses this challenge by constructing ToolBench—a large-scale instruction-tuning dataset spanning over 16,000 real-world APIs—and utilizing a depth-first search (DFS) decision tree algorithm alongside a neural API retriever to explore complex instruction trajectories [6]. Similarly, Gorilla formulates tool augmentation as a constrained text generation problem, fine-tuning LLaMA models on massive API collections and integrating document retrievers to adapt dynamically to API documentation updates and minimize syntax hallucinations [8].

Evaluating tool-augmented agents has similarly driven the development of rigorous benchmarks. API-Bank evaluates models across 73 tool APIs and multi-turn dialogues (314 tool-use dialogues with 753 API calls), identifying persistent failure modes such as incorrect argument generation, failure to utilize retrieved APIs, and hallucinated tool calls [9]. In web environments, WebArena provides a reproducible, realistic enterprise web environment (covering e-commerce, forums, and content management systems) to evaluate agents on end-to-end multi-step navigation and visual reasoning, revealing that current agents struggle significantly with long-horizon web tasks [7]. Furthermore, SWE-bench pushes agents into repository-scale software engineering, evaluating models on 2,294 real-world GitHub issues across 12 Python repositories and demonstrating that resolving complex multi-file code editing remains exceptionally challenging [10].

## Safety, Robustness, and Security Vulnerabilities
Despite their utility, tool-integrated LLM agents present severe security risks stemming from the "lethal trifecta": possessing privileged tool access, processing untrusted external inputs, and maintaining external communication capabilities [14]. A prominent attack vector is Indirect Prompt Injection (IPI), where malicious instructions embedded in retrieved web pages, emails, or API outputs hijack the agent's reasoning trace. The InjecAgent benchmark evaluated 30 LLM agents across 1,054 test cases, revealing that ReAct-prompted GPT-4 exhibited a 23.6% attack success rate (ASR) that escalated to 47.0% under enhanced prompting, while Llama2-70B exceeded 80% ASR [12]. Furthermore, advanced end-to-end frameworks like AgentBreaker generate context-aware adversarial HTML elements tailored to web operating contexts, achieving attack success rates between 71.7% and 100% against state-of-the-art web agents [13].

Real-world security exploits have underscored these theoretical vulnerabilities. Comprehensive reviews document major incidents such as GitHub Copilot's CVE-2025-53773 remote code execution vulnerability (CVSS 9.6) and unauthorized license key exposures [14]. To counter these threats, defense-in-depth frameworks such as PALADIN have been proposed, combining input sanitization, context isolation, behavioral monitoring, tool sandboxing, and output verification [14]. Additionally, proactive step-level guardrails like TS-Guard (paired with the TS-Flow framework) monitor tool invocation requests and interaction history before execution, successfully reducing harmful tool calls by up to 65% while improving benign task completion by approximately 10% [15].

## Error Handling, Hallucination Detection, and Recovery
Error handling and recovery remain critical bottlenecks in multi-turn agent execution, where models frequently fall into repetitive invalid re-invocations when encountering tool execution failures. To address tool-calling hallucinations—such as selecting incorrect tools, generating malformed parameters, or bypassing tools entirely through text simulation—unsupervised single-pass classifiers trained on last-layer internal representations can detect hallucinations in real time with 72.7% to 86.4% accuracy (e.g., 86% precision on GPT-OSS-20B) without requiring multiple forward passes [16].

To enhance error recovery capabilities, reinforcement learning frameworks have been introduced. Fission-GRPO converts execution errors into on-policy corrective supervision by augmenting failed trajectories with diagnostic feedback from an Error Simulator and resampling recovery rollouts, improving Qwen3-8B error recovery rates by 5.7% absolute and boosting multi-turn benchmark performance by up to +17.4% [17]. Complementarily, structured reflection frameworks train agents to explicitly localize and diagnose tool execution errors using prior evidence before generating a corrected call, leveraging multi-dimensional reward mechanisms (format executability, parameter correctness, and semantic consistency) to significantly improve multi-turn tool-call success rates [18].

## Trends and Open Problems
The field of LLM agents and tool use is rapidly shifting toward robust, self-correcting, and secure autonomous ecosystems. Key emerging trends include the transition from brittle reactive loops to global planning architectures (DAG planners and reinforcement-learned planners), the integration of rigorous step-level runtime guardrails (TS-Guard and PALADIN), and the adoption of advanced alignment methodologies like GRPO and structured reflection to master error recovery [4][15][14][17][18].

Despite these advances, several critical open problems remain unsolved:
1. **Robustness Against Adaptive Adversaries:** Current defenses against indirect prompt injections and context-aware web attacks remain susceptible to sophisticated jailbreaks and prompt-mutating attackers, necessitating provably secure agent sandboxes and context isolation [12][13][14].
2. **Long-Horizon Generalization and Efficiency:** While benchmarks like SWE-bench and WebArena reveal severe performance dropoffs over extended interaction horizons, developing efficient search and planning algorithms that scale to thousands of reasoning steps remains an open challenge [7][10].
3. **Internal Representation Monitoring vs. External Validation:** Balancing low-latency internal-state hallucination detection with comprehensive external tool verification is essential for real-time safety gating in production environments [16].
4. **Standardized Multi-Agent Security Protocols:** As multi-agent frameworks (AutoGen, LangGraph) scale to enterprise deployments, establishing cryptographic and policy-governed communication standards across distributed agent networks is vital to prevent cascading failures and unauthorized tool exploitation [3][5][14].
